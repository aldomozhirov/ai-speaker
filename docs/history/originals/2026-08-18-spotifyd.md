# Raspberry Pi 5: spotifyd + PipeWire + CamillaDSP

This document records the Spotify playback configuration for the AI Speaker,
including the existing PipeWire, ALSA Loopback, CamillaDSP, HiFiBerry,
GPIO-button, and volume-LED setup.

## 1. Current audio architecture

```text
Spotify Connect
      |
      v
spotifyd 0.4.2 (PulseAudio backend, MPRIS)
      |
      v
PipeWire-Pulse user server
      |
      v
PipeWire default sink: ALSA Loopback playback
      |
      v
ALSA Loopback capture
      |
      v
CamillaDSP
      |
      v
HiFiBerry DAC+ / amplifier / speakers
```

spotifyd must use the PipeWire-Pulse compatibility server. It must not open
the HiFiBerry or ALSA Loopback hardware directly; CamillaDSP remains the only
process that owns the physical HiFiBerry output.

The Raspberry Pi is currently reachable as `aldom@<pi-address>` and uses the
Linux user `aldom` with UID `1000`.

## 2. Why spotifyd

spotifyd was chosen as the Spotify playback provider because it combines the
capabilities needed by this speaker with a clean local control interface:

- Spotify Connect makes the speaker selectable from the official Spotify app.
- MPRIS exposes play/pause, next/previous, playback state, and volume-related
  controls to local software such as `playerctl`.
- Its PulseAudio backend joins PipeWire through the existing compatibility
  server, keeping CamillaDSP as the single owner of the physical audio output.
- It runs naturally as an `aldom` user service, matching the user-scoped
  PipeWire and D-Bus sessions used by the speaker.
- The MPRIS boundary can later be wrapped by one provider-neutral
  `media-orchestrator`, allowing the same button and voice-control API to work
  with Spotify, VLC, and a future browser/YouTube adapter.

This keeps Spotify-specific behavior inside the spotifyd adapter while
leaving the rest of the speaker architecture reusable for other media
providers.

## 4. Build spotifyd from source

The Debian-provided Rust toolchain was too old for the selected spotifyd
release, so Rustup was installed for the `aldom` user. The active toolchain
used for the build was Rust/Cargo 1.97.1.

Build dependencies installed with apt:

```bash
sudo apt update
sudo apt install -y \
  libssl-dev \
  libpulse-dev \
  libdbus-1-dev \
  libasound2-dev \
  pkg-config \
  cargo \
  rustc
```

The official spotifyd v0.4.2 source was built with the PulseAudio backend and
session-bus MPRIS support:

```bash
mkdir -p ~/.cache/spotifyd
git clone --branch v0.4.2 \
  https://github.com/Spotifyd/spotifyd.git \
  ~/.cache/spotifyd/src-v0.4.2

cd ~/.cache/spotifyd/src-v0.4.2

# Copy media-control/spotifyd-no-mixer-volume.patch to /tmp on the Pi before
# running this command. Apply it only once per source checkout. It makes the
# no-mixer controller remember the logical volume without adding a second
# audio attenuation stage.
git apply /tmp/spotifyd-no-mixer-volume.patch

cargo build --release --locked \
  --no-default-features \
  --features pulseaudio_backend,dbus_mpris

install -Dm755 target/release/spotifyd ~/.local/bin/spotifyd
~/.local/bin/spotifyd --version
# spotifyd 0.4.2
```

The binary is installed at:

```text
/home/aldom/.local/bin/spotifyd
```

The workspace patch is
[`media-control/spotifyd-no-mixer-volume.patch`](media-control/spotifyd-no-mixer-volume.patch).
It is required with `volume_controller = "none"`: spotifyd asks its mixer for
the current volume when playback starts, and the unpatched no-mixer
implementation reports 100% instead of retaining the logical MPRIS volume.
The patch makes that controller stateful while still leaving audio gain to
PipeWire. The installed `/home/aldom/.local/bin/spotifyd` binary was rebuilt
with this patch.

## 5. spotifyd configuration

The workspace copy is
[`spotifyd/spotifyd.conf`](spotifyd/spotifyd.conf).

The live copy is:

```text
/home/aldom/.config/spotifyd/spotifyd.conf
```

Current configuration:

```ini
[global]

device_name = "AI Speaker"
device_type = "speaker"

use_mpris = true
dbus_type = "session"

backend = "pulseaudio"
bitrate = 320

# PipeWire is the single physical volume authority. The local volume bridge
# mirrors this value into spotifyd's MPRIS interface for Spotify Connect.
volume_controller = "none"
initial_volume = 100

cache_path = "/home/aldom/.cache/spotifyd"
no_audio_cache = false
autoplay = false
```

Important choices:

- `device_name` makes the receiver appear in Spotify as **AI Speaker**.
- `backend = "pulseaudio"` joins the existing PipeWire-Pulse route.
- `use_mpris = true` exposes playback controls through MPRIS, allowing
  `playerctl` and future provider-neutral control code to use the same local
  interface.
- `dbus_type = "session"` matches the user-scoped PipeWire and D-Bus session.
- `volume_controller = "none"` prevents a second software attenuation stage;
  the shared volume synchronizer mirrors the PipeWire value into MPRIS.
- No Spotify credentials are stored in the configuration. Authentication is
  completed through Spotify Connect and the local spotifyd cache.

## 6. User systemd service

The workspace copy is
[`spotifyd/spotifyd.service`](spotifyd/spotifyd.service).

The live unit is:

```text
/home/aldom/.config/systemd/user/spotifyd.service
```

```ini
[Unit]
Description=spotifyd Spotify Connect receiver
Documentation=https://docs.spotifyd.rs/
Wants=network-online.target
After=network-online.target pipewire-pulse.service

[Service]
Type=simple
ExecStart=/home/aldom/.local/bin/spotifyd --no-daemon --config-path=/home/aldom/.config/spotifyd/spotifyd.conf
Restart=on-failure
RestartSec=5
Environment=XDG_RUNTIME_DIR=/run/user/1000
Environment=PULSE_SERVER=unix:/run/user/1000/pulse/native
Environment=DBUS_SESSION_BUS_ADDRESS=unix:path=/run/user/1000/bus

[Install]
WantedBy=default.target
```

Enable or restart it with:

```bash
systemctl --user daemon-reload
systemctl --user enable --now spotifyd.service
systemctl --user restart spotifyd.service
```

The service is intentionally user-scoped. This gives spotifyd access to the
same PipeWire-Pulse socket and session D-Bus used by the rest of the speaker.

```text
/home/aldom/.config/systemd/user/volume-buttons.service
```

The script is:

```text
/home/aldom/.local/bin/volume-buttons.py
```

Current behavior:

| Button | Action |
|---|---|
| Volume up | Increase the PipeWire default sink by 5% |
| Volume down | Decrease the PipeWire default sink by 5% |
| Playback single press | `playerctl play-pause` |
| Playback double press | `playerctl next` |

The playback button is now controlling spotifyd through its MPRIS player. The
MPRIS player can be inspected with:

```bash
playerctl --list-all
playerctl status
```

## 8. Bidirectional volume synchronization

The volume synchronization service is stored in the workspace as
[`media-control/volume_sync.py`](media-control/volume_sync.py) and
[`media-control/volume-sync.service`](media-control/volume-sync.service).

The live files are:

```text
/home/aldom/.local/bin/volume_sync.py
/home/aldom/.config/systemd/user/volume-sync.service
```

spotifyd uses no local volume controller:

```ini
volume_controller = "none"
```

This leaves PipeWire as the one physical volume stage:

```text
Spotify remote volume -> spotifyd MPRIS -> volume-sync -> PipeWire master volume
GPIO volume buttons ---------------------------> PipeWire master volume
PipeWire master volume -> volume-sync -> spotifyd MPRIS -> Spotify remote state
```

The synchronizer:

- watches the spotifyd MPRIS `Volume` property through the session D-Bus;
- polls the PipeWire default sink every 250 ms so GPIO and other local clients
  are reflected remotely;
- clamps both directions to the MPRIS range `0.0`–`1.0`;
- suppresses duplicate updates to avoid feedback loops;
- initializes a newly available spotifyd MPRIS player from the current
  PipeWire master volume.

The service is user-scoped and enabled for boot-time startup. It remains
available even when spotifyd has no active Spotify session; the MPRIS player
appears when Spotify connects to the speaker.

The ReSpeaker volume LED follows the same PipeWire sink state, so the button,
remote Spotify volume, and LED share one physical volume value.

The spotifyd build includes the workspace
[`media-control/spotifyd-no-mixer-volume.patch`](media-control/spotifyd-no-mixer-volume.patch).
Without it, spotifyd's no-mixer implementation reports 100% when playback is
started and can overwrite the synchronized PipeWire volume. The patch retains
the logical MPRIS volume while keeping PipeWire as the only audio gain stage.

The synchronizer also ignores spotifyd's initial cached MPRIS volume while a
new player is being attached. This prevents the cached startup value from
overwriting the current PipeWire value during Spotify Connect setup.

The live behavior was verified with both transitions:

- `0.42` remained `0.42` when toggling playback from playing to paused.
- `0.37` remained `0.37` when pressing play from paused.

Useful live checks:

```bash
systemctl --user is-enabled volume-sync.service
systemctl --user is-active volume-sync.service
systemctl --user status volume-sync.service
wpctl get-volume @DEFAULT_AUDIO_SINK@
playerctl --list-all
playerctl --player=spotifyd volume
```

To exercise the remote direction, select **AI Speaker** in Spotify and change
the Spotify volume. The PipeWire value should follow. To exercise the local
direction, press either GPIO volume button; the Spotify volume should follow
after the synchronizer's short polling interval.

## 9. Provider-neutral control architecture

The future control layer should keep provider-specific playback behind one
local API:

```text
GPIO buttons ─┐
Voice control ─┼─> media-orchestrator API ─┬─> spotifyd / MPRIS
Remote clients ┘                          ├─> VLC / MPRIS
                                          └─> browser adapter later
```

The orchestrator should provide actions such as:

```text
play, pause, play_pause, next, previous,
set_volume, adjust_volume, get_state
```

Spotifyd and VLC can use MPRIS adapters. Browser playback, such as YouTube,
will need a browser-specific adapter, but it should expose the same
provider-neutral actions. The volume synchronizer is the first shared
media-control component. Future voice commands should call this same API
rather than controlling spotifyd directly.

## 10. Validation commands

Run these as the `aldom` user unless a command is explicitly prefixed with
`sudo`:

```bash
# spotifyd service
systemctl --user is-enabled spotifyd.service
systemctl --user is-active spotifyd.service
systemctl --user status spotifyd.service --no-pager
systemctl --user is-enabled volume-sync.service
systemctl --user is-active volume-sync.service
systemctl --user status volume-sync.service --no-pager

# Spotify Connect discovery
avahi-browse -rt _spotify-connect._tcp

# MPRIS playback control
playerctl --list-all
playerctl status
playerctl play-pause
playerctl next

# PipeWire route
wpctl status
wpctl get-volume @DEFAULT_AUDIO_SINK@

# Supporting services
systemctl --user is-active pipewire pipewire-pulse wireplumber
systemctl is-active camilladsp avahi-daemon
```

Expected current state:

- spotifyd is enabled and active.
- Spotify Connect advertises **AI Speaker**.
- `playerctl` sees a player named similar to `spotifyd.instance<PID>` while a
  Spotify session is active.
- The PipeWire default sink remains the Loopback route used by CamillaDSP.
- Volume buttons, PipeWire, spotifyd MPRIS, and the Spotify remote volume use
  the same synchronized volume value.
- spotifyd is the only Spotify playback receiver.

## 11. Updating the local configuration

After changing either workspace file, copy it to the corresponding live path
and reload the user service:

```bash
scp spotifyd/spotifyd.conf aldom@<pi-address>:/tmp/spotifyd.conf
ssh aldom@<pi-address> \
  'install -Dm600 /tmp/spotifyd.conf /home/aldom/.config/spotifyd/spotifyd.conf'

scp spotifyd/spotifyd.service aldom@<pi-address>:/tmp/spotifyd.service
ssh aldom@<pi-address> \
  'install -Dm644 /tmp/spotifyd.service /home/aldom/.config/systemd/user/spotifyd.service'

scp media-control/volume_sync.py aldom@<pi-address>:/tmp/volume_sync.py
ssh aldom@<pi-address> \
  'install -Dm755 /tmp/volume_sync.py /home/aldom/.local/bin/volume_sync.py'

scp media-control/volume-sync.service aldom@<pi-address>:/tmp/volume-sync.service
ssh aldom@<pi-address> \
  'install -Dm644 /tmp/volume-sync.service /home/aldom/.config/systemd/user/volume-sync.service'

ssh aldom@<pi-address> \
  'systemctl --user daemon-reload && systemctl --user restart volume-sync.service && systemctl --user restart spotifyd.service'
```

Do not put Spotify credentials or secrets into the workspace configuration.
